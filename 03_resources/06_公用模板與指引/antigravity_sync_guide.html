🚀 跨裝置無縫接關工作流

Antigravity 跨裝置雲端同步與對話整合指南

手把手帶您利用雲端硬碟（Google Drive / OneDrive）實現雙電腦無縫漫遊，並將兩台電腦既有的分散對話歷史安全合併。

🧠

1. 核心本質差異：雲端 Agent vs. 本地優先 (Local-First)

為什麼像 ChatGPT / Claude 可以開網頁就繼續，而 Antigravity 需要同步機制？

ChatGPT / Claude (Cloud-First)

雲端運算
  • • 對話紀錄、上下文皆存放在 OpenAI / Anthropic 伺服器資料庫。
  • • 任何裝置登入同一帳號即可無感漫遊。
  • • 缺乏對開發者本地終端機、本地檔案與私有硬體的直接原生控制。

Antigravity (Local-First)

本機運作
  • • 直接運行於本地主機，擁有完整的本機終端、檔案讀寫與編譯能力。
  • • 思考過程與對話記憶儲存在本機的 brain/ 目錄中。
  • • 只需同步本機資料夾，就能獲得媲美雲端產品的跨裝置體驗！
📂

2. Antigravity 本地資料結構拆解

要達成跨電腦同步，我們只需要針對以下兩個關鍵核心資料夾做處理：

🗂 對話歷史與大腦記憶 (Brain)
C:\Users\<使用者>\.gemini\antigravity\brain\<UUID>\

存放每個對話的 transcript.jsonl、計畫 implementation_plan.md 與暫存檔案。

最關鍵：必同步
⚙️ 全域技能與外掛設定 (Config)
C:\Users\<使用者>\.gemini\config\

存放自訂 Skills、MCP 工具整合設定（mcp_config.json）與客製 Prompt。

建議同步
🛠️

3. 實作：利用 Google 雲端硬碟 + 目錄聯結 (mklink)

💡 Google 雲端硬碟電腦版設定：串流檔案 vs. 雙向同步 (鏡像檔案)
🌟 首選推薦：雙向同步 (即 鏡像檔案 / Mirror files)

於 Google Drive 偏好設定中選擇「雙向同步」（部分版本翻譯為鏡像檔案），並指定本地硬碟路徑（例如 C:\Users\Kevin\我的雲端硬碟\ 或自訂磁碟）。
優點：檔案已 100% 存在本機實體 NTFS 硬碟，天然免設離線、無占位符問題，且 mklink /J 保證 100% 成功！

⚡ 次選方案：串流檔案 (Stream files)

若使用虛擬磁區代號（例如 H:\我的雲端硬碟\）：
必須設定：在資料夾點右鍵 ➔ 「離線存取」➔ 勾選「可供離線使用」。
注意：虛擬磁區可能不支援 Junction，若報錯請改用符號連結 mklink /D。

1

在 Google 雲端硬碟建立中央同步資料夾

在 Google Drive 中建立專屬存放目錄，例如：

D:\GoogleDrive\AntigravitySync\
├── brain\
└── config\
⚠️ 關鍵設定：如何避免檔案變成即時下載的「占位符」？
  • 若為雙向同步 / 鏡像模式：所有檔案已自動存於本機實體硬碟，不需任何額外設定，最省心！
  • 若為串流模式 (Stream)：在該資料夾點右鍵 ➔ 選擇 「離線存取 (Offline access)」➔ 勾選「可供離線使用 (Available offline)」。
  • Windows 11 使用者請注意：新版右鍵選單若找不到，請點最下方「顯示其他選項」（或直接按快捷鍵 Shift + F10）即可展開 Google Drive 選單！
2

將電腦 A 的本機目錄連結到 Google 雲端

完全關閉 Antigravity，將本地現有的 brain 與 config 內容搬移至 Google Drive 雲端目錄後，以系統管理員身分開啟 Windows CMD 執行：

:: 【首選：雙向同步 (鏡像) / 實體本機路徑 (如 C:\Users\Kevin\我的雲端硬碟\... 或 D:\GoogleDrive\...)】使用 /J (Junction)
mklink /J "C:\Users\<你的用戶名>\.gemini\antigravity\brain" "C:\Users\<你的用戶名>\我的雲端硬碟\AntigravitySync\brain"
mklink /J "C:\Users\<你的用戶名>\.gemini\config" "C:\Users\<你的用戶名>\我的雲端硬碟\AntigravitySync\config"
:: 【備選：串流模式 / 虛擬磁區 (如 H:\我的雲端硬碟\...)】若 /J 提示不支援磁區，請改用 /D (軟連結)
mklink /D "C:\Users\<你的用戶名>\.gemini\antigravity\brain" "H:\我的雲端硬碟\AntigravitySync\brain"
mklink /D "C:\Users\<你的用戶名>\.gemini\config" "H:\我的雲端硬碟\AntigravitySync\config"
3

在電腦 B 設定相同的目錄連結

電腦 B 也登入同一個 Google 帳號並同步完畢後，同樣在電腦 B 以管理員 CMD 建立連結指向同一個 Google Drive 目錄。此時電腦 B 與電腦 A 即可共享所有對話記憶與客製技能！

🔄

4. 電腦 A 與電腦 B 已有分散歷史對話？如何整合！

若兩台電腦在過去這段時間各自獨立產生了大量對話，請放心：完全不會發生檔名覆蓋與衝突！

💡 為什麼能無痛合併？

Antigravity 的每一個 Conversation 都是以全域唯一的 UUID 識別碼（如 ae9c96a0-e682-465b...）作為資料夾名稱。電腦 A 與電腦 B 所產生的 UUID 絕不會相同，因此對話歷史本質上是自然聯集 (Union)。

步驟 A 先備份兩台電腦原始檔

在電腦 A 與 B 分別複製 .gemini 資料夾作為安全備份（如命名為 .gemini_backup），並退出 Antigravity。

步驟 B 合併 Brain (大腦對話)

先將電腦 A 的 brain/ 內所有 UUID 資料夾複製到雲端；接著將電腦 B 的 brain/ 內所有資料夾也複製進同一個雲端目錄（兩者聯集）。

步驟 C 手動合併 Config 設定

比對兩邊的 skills/ 將特有技能合流；若兩邊都有修改 mcp_config.json，手動將 MCP Server 項目整合成同一份 JSON。

步驟 D 清理並掛載 Junction

刪除兩台電腦原地的 brain 與 config，執行 mklink /J 指向已合流的雲端總目錄。

🎯

5. 跨電腦切換與「接關」最佳實踐

心法 1：避免兩台電腦同時開啟寫入

在電腦 A 結束工作時，關閉 Antigravity，等待雲端硬碟同步圖示打勾（約 10~30 秒），再於電腦 B 開啟。可徹底避免日誌寫入時的雲端衝突檔。

心法 2：路徑適應提示（最重要的接關咒語）

電腦 A 上的專案可能是 C:\Users\A\Projects\App，而電腦 B 可能是 D:\Work\App。當你在電腦 B 點開電腦 A 的歷史對話時，第一句話請傳送：

「我現在換到了電腦 B，當前專案工作目錄路徑為 D:\Work\App，請基於這個路徑與先前的討論進度繼續執行。」

心法 3：程式碼專案採用 Git 協同

程式碼本體透過 Git 進行 git push / pull；Antigravity 產生的 implementation_plan.md 與專案規範 .agents/ 也納入版本控制，達到雙保險。
