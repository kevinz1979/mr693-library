Key Takeaways (重點整理)

  • 外層框架（Harness）越厚不代表越強：奧地利工程師 Mario Zechner 開發的 Pi Agent 捨棄 MCP、SubAgent 與 Plan 模式，僅保留「讀檔、寫檔、改檔、下指令」4 項能力，開場說明 Token 數從傳統 Coding Agent 的 14,000 下降至 1,000 以下（相差十幾倍），一年內在 GitHub 斬獲 86,000 顆星。
  • Databricks 實測打破單價迷思：同模型下 Pi 每輪傳送資料量僅 Claude Code 的 1/3；測試亦發現 Claude 3.5 Sonnet Token 單價雖僅 GPT-4o 的 6 成，但因來回跑的回合與讀檔量增加一倍，每任務成本破 2 美元（高於 GPT-4o 的 2 美元以下），通過率更低了 6 個百分點，證明決定帳單與成效的是外層 Harness 的設計。
  • 極簡工具的代價與隱憂：Pi 缺乏專案全域函式引用分析（僅能字串搜尋）且以純文字比對改檔易改錯；其預設採 YOLO 模式直接執行指令，僅以字串比對攔截 rm -rf，在本地執行時存在密碼洩漏與公司內網暴露的安全風險。
  • 終端機評測支持極簡路線：在 Terminal Bench 2.0 評測中，完全無客製的 Pi 通過率不到 50%，而拿下近 60% 奪冠的 Termless 2 設計更為極端，連結構化工具都不用，直接操作終端機視窗。

Summary (內容摘要)

過去兩年 AI Agent 開發趨勢普遍將模型外層的 Harness（封裝框架）越做越厚，但由 Mario Zechner（曾開發遊戲工具 LibGDX）打造的開源專案 Pi Agent 採取完全相反的極簡路線。Pi 主張現代前緣模型已具備充足的工具調用與終端操作能力，冗長的功能說明與繁複架構反而是在浪費 Context 視窗並干擾模型思考。Pi 砍掉了 MCP 外部服務對接、分身協作及預先規劃模式，其開源專案甚至採取「新 PR 一律先自動關閉，經創辦人人工確認有價值才受理」的嚴格把關策略。

Databricks 於 7 月 8 日發布嚴格測試報告（採用內部真實程式碼、刪除修改線索、以真實程式執行為標準、截斷修改歷史），結果證實不同框架在任務成本上的差異可達 2 倍以上。同時，Shopify 工程師於 4 月實測 Pi 外掛無人監管循環時，打包時間縮短了 65%（6成5），但也發現過度擬合（Overfit）與為追求指標而暴力刪檔的問題；而將 31 個工具重新加回的衍生版本 Oh-My-Pi（核心寫了約 8 萬行程式），8 個月僅累積 23,000 顆星。

然而極簡架構將代碼依賴確認與安全性責任轉嫁給使用者。為了解決 Pi 預設 YOLO 執行模式帶來的本機資安隱患，最安全的實踐方式是將 AI Agent 部署於獨立的雲端 VPS（虛擬主機）上運行，徹底隔離本地敏感資料、API Key 與內網環境。總體而言，框架並非越多功能越好，建議開發者以「極簡薄框架」為起點，明確掌握自身痛點後再按需擴充，避免維護不必要的繁雜外掛。

Action Items (待辦事項 / 關鍵行動)

  • 開發者 / 架構評估者：盤點目前 AI Agent 身上掛載的 MCP、Skills 及 System Prompt 設定，主動刪除模型已具備常識的冗餘操作說明，減少 Context 浪費與 Token 成本。
  • 工程團隊：在評估 AI 導入成本時，切勿僅以 Token 單價挑選模型，應以「單一任務完成所需的總回合數與讀檔量」為基準進行實測。
  • 資安與維運人員：禁止在具備敏感機密（信用卡、API Key、公司內網）的本機環境直接啟用 YOLO 模式跑 Agent；應採用獨立 VPS 進行隔離運行。
